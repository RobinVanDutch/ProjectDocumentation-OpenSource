# Spec Delta

## Purpose

Раздел встреч в офисе должен читаться однозначно: одно место, где видно все встречи, понятный
переключатель представления, работающие группировка и сортировка, форма создания, которая сразу
спрашивает тип встречи, и никакого пути «встреча без календаря». Дельта закрывает два дефекта QA
(контраст кнопки, пустые группировка/сортировка) и фиксирует требования по объединению
представлений, группам в навигаторе и окну создания.

## ADDED Requirements

### Requirement: Читаемые подписи кнопок в обеих темах

Любая кнопка со подписью MUST оставаться читаемой в светлой и тёмной темах во всех состояниях,
включая `hover` и `active`. Контраст текста MUST быть не ниже 4.5:1.

#### Scenario: Наведение на «Новая группа» в светлой теме

- **WHEN** пользователь включает светлую тему и наводит курсор на кнопку «Новая группа» в шапке
  раздела «Постоянные встречи»
- **THEN** подпись видна и читается; цвет текста не совпадает с цветом фона ни в обычном состоянии,
  ни при наведении

#### Scenario: Та же кнопка в тёмной теме

- **WHEN** тема тёмная
- **THEN** подпись читается так же; правка не ухудшила контраст относительно текущего поведения

### Requirement: Рабочая группировка и сортировка списка постоянных встреч

Экран постоянных встреч MUST предлагать не менее трёх вариантов группировки (`group`, `members`,
`private`) и сортировку по названию, дате создания и дате изменения. Выбранные группировка и порядок
MUST сохраняться в настройках вида пользователя и переживать перезагрузку страницы. Колонка, которую
нельзя осмысленно отсортировать, MUST NOT попадать в список сортируемых.

#### Scenario: Группировка по группе встреч

- **WHEN** пользователь выбирает группировку «Группа» в настройках вида
- **THEN** список разбит на секции по группам в их порядке; встречи без группы идут последней
  секцией; пустых секций с нулём строк не показывается

#### Scenario: Сортировка по названию после перезагрузки

- **WHEN** пользователь выбирает сортировку по названию по возрастанию и перезагружает страницу
- **THEN** порядок строк соответствует выбранному; дропдаун сортировки показывает выбранное значение,
  а не пустой список

### Requirement: Встреча всегда связана с календарём

Создание постоянной встречи MUST NOT предлагать вариант «не показывать в календаре». Любая созданная
встреча MUST иметь связанную серию (мастер-событие с миксином `MeetingEventLink`) или одиночное событие
календаря. Существующие документы без серии MUST продолжать открываться.

#### Scenario: Создание встречи из раздела постоянных встреч

- **WHEN** пользователь нажимает «Новая встреча» и сохраняет форму
- **THEN** в окне нет переключателя «Показывать в календаре»; встреча появляется и в разделе встреч,
  и в календаре; в базе нет `PermanentMeeting` без серии

#### Scenario: Старая встреча без серии

- **WHEN** открывается `PermanentMeeting`, созданная до изменения и не имеющая серии
- **THEN** карточка и вход работают как раньше; изменить её тип на «без календаря» больше нельзя

### Requirement: Первый шаг создания встречи — тип встречи

Окно создания MUST начинать с выбора «Разовая» или «Повторяющаяся». Поля повторения MUST показываться
только для повторяющейся встречи. Для существующей встречи шаг MUST отражать её фактический тип;
смена типа с повторяющейся на разовую MUST требовать явного подтверждения.

#### Scenario: Создание разовой встречи

- **WHEN** пользователь выбирает «Разовая» и заполняет форму
- **THEN** полей периода повторения нет; создаётся одиночное событие без правила

#### Scenario: Создание повторяющейся встречи

- **WHEN** пользователь выбирает «Повторяющаяся»
- **THEN** появляются период повторения и правило; создаётся серия, участники и ссылка — как сейчас

#### Scenario: Смена типа у существующей серии

- **WHEN** у повторяющейся встречи пользователь выбирает «Разовая» и подтверждает
- **THEN** серия становится одиночным событием; без подтверждения тип не меняется
