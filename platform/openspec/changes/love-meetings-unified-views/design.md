# Design: как это делается

## 1. QA-1. Контраст текста у «Новой группы» на hover (светлая тема)

**Где.** Кнопка — `plugins/love-resources/src/components/PermanentMeetingsHeaderActions.svelte:40`:

```svelte
<Button icon={view.icon.List} label={love.string.CreateMeetingGroup} kind="secondary" on:click={createGroup} />
```

**Механизм.** `packages/ui/src/ui-kit/button/Button.svelte`, блок `&--secondary`: label берётся из
`--kit-button-subtle-LabelColor`, а hover меняет только фон (`--_bg-hover`). Если в светлой теме
`--kit-button-subtle-LabelColor` рассчитан на тёмную подложку, текст сливается с фоном при наведении.

**Порядок проверки (важен: не чинить глобально, если дефект локальный).**

1. Воспроизвести на стенде в светлой теме и снять вычисленные значения
   `color`, `background-color` кнопки, а также `--kit-button-subtle-LabelColor`,
   `--kit-button-secondary-hover-BackgroundColor` в DevTools.
2. Если промах в токенах темы — править токен (одно место, чинит все такие кнопки).
3. Если дефект только у кнопок в шапке вьюлета (у `NavItem`/`IconButton` рядом контраст в норме) —
   править компонент кнопки либо передать другой `kind` (`tertiary` уже использует
   `--global-secondary-TextColor` и на hover темнеет, а не бледнеет).
4. Критерий: при наведении текст читается при контрасте не ниже 4.5:1 в обеих темах.

**Риск.** Правка токена меняет вид всех secondary-кнопок — принимается только после просмотра
пары экранов (список встреч, настройки офиса).

## 2. QA-2. Пустые группировка и сортировка у постоянных встреч

**Где.** `models/love/src/index.ts`, вьюлеты `love.viewlet.TablePermanentMeetings` (~строка 945) и
`love.viewlet.ListPermanentMeetings` (~строка 975):

```ts
// таблица
viewOptions: { groupBy: [], orderBy: [['name', SortingOrder.Ascending]], other: [] }
// список
viewOptions: { groupBy: ['group', 'members', 'private', 'createdBy'], orderBy: [['name', ...]] }
```

Конфиг колонок: `config: ['', {presenter: PermanentMeetingNextPresenter, displayProps.key: 'next'},
{key:'members'}, {presenter: PermanentMeetingLastSessionPresenter, displayProps.key: 'lastEnd'}]`.
Скрытые ключи: `MODEL_HIDDEN_KEYS` (`description`, `descriptionRef`, `meetingAccess`, `linkId`,
`linkVersion`, `type`, `language`, `messages`, `attachments`, `repeatEvery`).

**Вероятные причины (проверить по порядку).**

1. **У таблицы `groupBy: []`** — в настройках вида нет ни одной группы по умолчанию, дропдаун пуст.
2. **Колонки без `key`** (`''`, `next`, `lastEnd`) не дают ключей сортировки: `buildModel` выводит
   `sortingKey` из `preserveKey.sortingKey ?? preserveKey.key`, а у них ключ пустой или синтетический —
   сортировать по «Следующее вхождение» и «Последняя сессия» нельзя до появления `sortingKey`.
3. **`group` как ключ группировки** — проверить, что он вообще доступен в настройках: атрибут объявлен
   в модели и не скрыт в `MODEL_HIDDEN_KEYS` (сейчас не скрыт), но значение должно быть разрешаемым
   (`canResolveAttribute`), а у группы нет presenter'а для подписи, если `PermanentMeetingGroupPresenter`
   не зарегистрирован как `AttributePresenter` (зарегистрирован — см. `models/love/src/index.ts`).
4. **Пустой результат** — «пустая группировка» может означать «нет ни одной встречи без группы»:
   если все встречи в группе, секция «Без группы» пуста и выглядит как баг.

**Критерий.** В настройках вида есть минимум три рабочих варианта группировки (`group`, `members`,
`private`) и сортировка по названию, дате создания и дате изменения; выбранные значения сохраняются
в preference и переживают перезагрузку.

## 3. QA-4. Убрать создание встречи без календарной серии

**Где.**

- `plugins/love-resources/src/components/PermanentMeetingForm.svelte`: проп `allowNoCalendar` (строка 49)
  и блок `{#if allowNoCalendar && object === undefined}` с тогглом `ShowInCalendar` (`inCalendar`).
- `plugins/love-resources/src/components/CreatePermanentMeetingPopup.svelte`: передаёт `allowNoCalendar`.
- `plugins/love-resources/src/components/PermanentMeetingsHeaderActions.svelte`: `createMeeting` →
  `showPopup(CreatePermanentMeetingPopup, { space, allowNoCalendar: true }, 'top')` — единственное место,
  где этот путь включён.

**Решение.** Удалить проп и тоггл; постоянная встреча всегда создаёт серию (или одиночное событие с
правилом «без повтора»), миксин `MeetingEventLink` вешается на мастер, ссылка пишется в `location`.
Строки `ShowInCalendar`, `ShowInCalendarHint` из локалей удалить только если больше не используются.

**Критерий.** В окне создания нет переключателя «Показывать в календаре»; созданная встреча всегда
видна в календаре и в разделе встреч; в БД нет `PermanentMeeting` без связанной серии.

## 4. QA-6. Первый шаг формы — тип встречи

**Сейчас.** `PermanentMeetingForm` сразу показывает название, дату/время, период повторения, гостевой
пароль, участников (и тоггл календаря, который удаляется по QA-4). Поле повторения — `RepeatEveryEditor`
с `period` (мс, `object?.repeatEvery ?? WEEK`).

**Предлагаемая структура (один компонент, ветвление блоков).**

| Шаг                   | Элементы                                        | Показывать             |
| --------------------- | ----------------------------------------------- | ---------------------- |
| 1. Тип                | переключатель «Разовая» / «Повторяющаяся»       | всегда                 |
| 2. Время              | `EventTimeEditor`                               | всегда                 |
| 3. Повтор             | `RepeatEveryEditor`, правило, конец серии       | только «Повторяющаяся» |
| 4. Участники и доступ | `AccountArrayEditor`, пароль гостя, напоминание | всегда                 |

При редактировании существующей встречи шаг 1 отражает её фактический тип (`RepeatEveryEditor`
пустой/`repeatEvery` отсутствует → разовая) и не позволяет «потерять» серию молча: смена типа на
«разовая» у повторяющейся — отдельное подтверждение с явным последствием (серия станет одиночным
событием).

**Критерий.** Пользователь не видит полей повторения, пока не выбрал «Повторяющаяся»; настройки
сохраняются в те же поля, что и сейчас (`repeatEvery`, `rules` мастера), новых сущностей нет.

### 4a. Макет окна создания (ревью владельца 2026-11-23)

Собран в Storybook: `Love/Create meeting` — `dev/storybook/src/love/CreateMeetingDialog.svelte`
(UIKit: `Dialog`, `Tabs`, `TextInput`, `TextArea`, `NumberInput`, `DateSelect`, `Dropdown`, `Toggle`,
`Checkbox`). Принятые решения:

| Решение                          | Детали                                                                                                                                                                               |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Две вкладки, не три              | «Постоянная» / «Разовая». Скрытая встреча — это постоянная или разовая с выключенным тумблером «Показывать в календаре»; третья вкладка повторяла бы тот же тумблер                  |
| Тумблер «Показывать в календаре» | Есть в обеих вкладках и **редактируемый** (не readonly): выкл = встреча только ссылкой, без серии                                                                                    |
| Связанные время/длительность     | Изменение начала сдвигает конец с сохранением длительности; перенос конца раньше начала тянет начало назад на ту же длительность                                                     |
| «Весь день»                      | Чекбокс над датами: время убирается из полей (выбор только даты), при выключении возвращаются прежние часы; чекбокс стоит **над** датами, иначе оба поля теряют место под свой текст |
| Часовой пояс                     | Отдельная строка выбора (текущий / UTC / Москва / Нью-Йорк); в макете — только выбор, хранение в событии — в задаче реализации                                                       |
| Единица повторения               | Не readonly-поле, а выпадающий список: дни / недели / месяцы                                                                                                                         |
| Напоминание                      | Чекбокс «Уведомить» включает набор отрезков — несколько выбираются сразу («за 15 минут», «за 1 час», «за 1 день»); без чекбокса отрезки недоступны                                   |
| Описание                         | Поле `TextArea` в общей сетке формы (было отдельным блоком в попапе события); высота растёт до 4 строк, дальше скролл                                                                |
| Участники                        | Поле ввода имени **или почты гостя** + кнопка «Добавить»                                                                                                                             |

**Отложено (не входит в эту дельту):** приглашение гостя на почту — письмо по введённому адресу при
добавлении участника. Сейчас отмечаем только точку входа (поле для почты), сам сценарий — задача
`2.3` в `tasks.md`.

## 5. QA-3 и QA-5. Единые представления и группы в навигаторе

**Решение владельца 2026-11-20 (Р1, Р2) — целевая структура. Уточнение владельца 2026-11-23 (Р3):
группы — отдельная вкладка со всеми группами, а календарь и создание встречи живут на вкладке
«Встречи» вместе с таблицей; отдельных наборов строк в «Группах» нет.**

### 5.1 Навигатор офиса

| Пункт          | Сегмент                                     | Содержимое                                                                                                           |
| -------------- | ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| Встречи        | `/love/meetings`                            | календарь и таблица, переключатель в шапке; создание встречи («Объединить в группу», «Новая встреча») — только здесь |
| Группы         | `/love/groups` (заменяет `/love/permanent`) | один список всех групп — постоянные встречи, сгруппированные по группе; из действий только «Объединить в группу»     |
| Этажи (группа) | `/love/<floorId>`                           | без изменений                                                                                                        |

Текущее состояние — `plugins/love-resources/src/components/OfficeNavigator.svelte`: пункты `meetings`
и `permanent` (`NavItem` с `_id`), состояние в `officeView`/`officeSegment` (`stores.ts`), центр
рисует `Hall.svelte` (ветки по `officeView`). Переименование пункта = новый сегмент + ветка в `Hall.svelte`

- миграция пользовательских ссылок (старый `/love/permanent` не должен давать 404 — редирект на `/love/groups`).

### 5.2 Вкладка «Встречи»: календарь и таблица

Реализовано (`MeetingsView.svelte`): два вида — «Календарь» и «Таблица», переключатель
`MeetingViewSwitch.svelte` (обёртка над `SegmentedControl`, `size="small"`, `iconOnly`) в слоте
`beforeTitle` шапки `SpecialView`.

- Календарь — вьюлет на миксине `MeetingEventLink` с `baseQuery { recurringEventId: { $exists: false } }`.
  Вид закреплён `descriptors={['calendar:viewlet:Calendar']}`: без этого побеждал ранее выбранный
  пользователем вьюлет (список), и вкладка открывалась списком.
- Таблица — `love.viewlet.TablePermanentMeetings` на `love.class.PermanentMeeting` с прежними колонками
  (Название · Следующее вхождение · Участники · Последняя сессия). Новый `TableScheduledMeetings`
  отменён.
- Список встреч отсюда убран — он живёт во вкладке «Группы» (см. 5.3).
- Настройки вида (`ViewOptionsButton` + шестерёнка) скрыты только у календаря (`hideViewSettings`):
  «Группировка и сортировка» для календаря бессмысленна. В таблице и списке групп они остаются.

Важное ограничение: календарь не умеет показывать `PermanentMeeting` (у него нет времени), поэтому
календарь остаётся по событиям, а невыраженные вхождения показываются в таблице и списке групп.

### 5.3 Вкладка «Группы»: один список всех групп

Реализовано (`MeetingGroupsView.svelte`): один `SpecialView` по `love.class.PermanentMeeting` со
штатным списком `ListPermanentMeetings` (группировка по `group`), без переключателя видов
(`descriptors={[view.viewlet.List]}`) и без поднабора «постоянные / без отображения».

- Три набора строк и переключатель наборов отменены решением владельца 2026-11-23: группа — это
  контейнер для встреч любого типа, поэтому одна вкладка = все группы с их встречами.
- Правый верх вкладки: только «Объединить в группу» (`createComponentProps={{ groupOnly: true }}`
  скрывает primary-кнопку «Новая встреча») — встреча создаётся на вкладке «Встречи».
- Хелпер `meetingSeries.ts` и его тесты удалены вместе с разделением наборов.

Тип встречи виден в строке списка и таблицы: иконка `love.icon.MeetingMinutes` (есть серия, встреча
в календаре) или `ui.icon.EyeSlash` (серии нет, встреча только ссылкой), плюс постоянная метка
`calendar.icon.Repeat` («постоянная встреча») с тултипом `love.string.PermanentMeeting`.

### 5.4 Что нельзя обойти

- Встречи и постоянные встречи — разные классы (`Event` + миксин против `PermanentMeeting: Space`).
  Один `Table`/`List`-вьюлет над двумя классами не выражается; нужен либо агрегатор, либо два
  набора данных под общим переключателем.
- Группа (`MeetingGroup`) — `core.class.Doc`, у неё нет времени, поэтому «календарь группы» — это
  календарь вхождений её встреч.
- Пункты навигатора включаются через `officeSegment`/`officeView`
  (`plugins/love-resources/src/stores.ts`, `OfficeNavigator.svelte`), центр рисует `Hall.svelte`;
  новый пункт = новый сегмент URL.

## Риски

| Риск                                                  | Митигация                                                                                                  |
| ----------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Правка токена кнопки меняет вид всех secondary-кнопок | Проверить 2–3 экрана обеих тем до коммита                                                                  |
| Смена типа встречи теряет серию                       | Подтверждение + тест на переход «серия → разовая»                                                          |
| Удаление «без календаря» ломает существующие встречи  | Данные не мигрируем: старые `PermanentMeeting` без серии продолжают открываться, закрываем только создание |
| Агрегатор двух классов ломает сортировку/фильтры      | Сначала только переключатель представлений, объединение данных — отдельным этапом                          |
