# Design: единый источник встреч

## 1. Решение

Встреча — это `love.class.PermanentMeeting`. `calendar.class.Event` — событие календаря/планировщика.
Одна встреча может быть связана с событием миксином `MeetingEventLink`, но списки раздела «Встречи»
строятся по `PermanentMeeting` и не зависят от наличия серии.

```
                  ┌──────────────────────────────┐
 создание из      │  CreateMeetingDialog          │
 «Встречи»  ─────►│  calendar: false               │──► PermanentMeeting (без серии)
                  └──────────────────────────────┘
                  ┌──────────────────────────────┐
 создание в       │  CalendarView / планировщик   │
 планировщике ───►│  calendar: true                │──► PermanentMeeting + Event (серия)
                  └──────────────────────────────┘
```

## 2. Хранение

| Что создаём             | Документы                                        | Видно в «Встречах» | Видно в «Группах» | Видно в планировщике |
| ----------------------- | ------------------------------------------------ | ------------------ | ----------------- | -------------------- |
| Постоянная из «Встреч»  | `PermanentMeeting` (`repeatEvery`, `startDate`)   | да                 | да                | нет                  |
| Разовая из «Встреч»     | `PermanentMeeting` (`startDate`, `duration`)      | да                 | да                | нет                  |
| Встреча из планировщика | `PermanentMeeting` (`calendar: true`) + `Event`   | да                 | да                | да                   |
| Обычное событие         | `Event` без миксина                               | нет                | нет               | да                   |

`calendar: false` — единственный признак «встреча не в календаре»; отсутствие поля означает серию
(так работают встречи, созданные до появления флага).

## 3. Модель

`TPermanentMeeting` получает:

```ts
@Prop(TypeNumber(), love.string.Duration)
duration?: number   // мс; конец встречи = startDate + duration

@Prop(TypeRef(love.class.Room), love.string.Room)
room?: Ref<Room>    // комната разовой встречи; у постоянной её нет
```

`duration` нужен разовой встрече: у постоянной длительность задаёт вхождение серии. `room` нужен по той же
причине: раньше комнату хранил миксин события, а разовая встреча больше не создаёт событие — без поля
выбор комнаты в форме потерялся бы (и сессия пошла бы в служебную комнату). У постоянной встречи `room`
остаётся пустым: её сессии идут в служебной комнате workspace.

Миграция `event-meeting-to-permanent` (mode `upgrade`) для каждого `Event` с миксином
`MeetingEventLink`, у которого поле `permanentMeeting` пустое:

1. создаёт `PermanentMeeting` (`name`, `startDate = date`, `duration = dueDate - date`, `members`,
   `timeZone`, `calendar: true`, `group` из миксина, если есть);
2. пишет `permanentMeeting` в миксин события;
3. событие и серию не удаляет — вход по ссылке и планировщик продолжают работать.

## 4. Форма создания

- Окно из **календаря раздела** (`date === undefined`): тумблер «Отображение в календаре» есть и включён по
  умолчанию. Включённый создаёт событие в **календаре встреч** — оно видно в календаре раздела и в списках,
  но не в Планировщике. Выключенный оставляет только документ встречи.
- Окно из **сетки календаря** (`date !== undefined`): тумблера нет, событие пишется в личный календарь —
  поэтому такие события видны и в Планировщике.
- Признак `series` в `PermanentMeetingInput` ставит только окно из планировщика, и только оно пишет событие
  в личный календарь (`ctx.calendarId`); всё остальное идёт в календарь `Meetings`
  (`meetingsCalendarId(me) = '<uuid>_meetings_calendar'`).
- Планировщик (`plugins/time-resources`) не читает календарь встреч: фильтр по суффиксу `_meetings_calendar`
  и в `WithTeamData.svelte`, и в `PlanningCalendar.svelte`.
- «Разовая» — дефолт; «Постоянная» — выбор табом, `period` из формы, `duration` = длительность вхождения.

## 5. Списки

- «Встречи» → таблица (`view.viewlet.Table`) и календарь — как сейчас, но строки теперь включают
  разовые и скрытые встречи, потому что все они `PermanentMeeting`.
- «Группы» → тот же класс, список с секциями по `group`; не меняется.
- Тип строки показывается иконкой: камера (есть серия) / перечёркнутый глаз (серии нет) — правило уже
  реализовано в `PermanentMeetingPresenter`.

## 6. Риски

| Риск                                                             | Мера                                                                                       |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| Миграция создаёт дубли, если запускается дважды                  | условие «у события нет `permanentMeeting`»; миграция идемпотентна                           |
| Старые встречи-события остаются без `duration`                   | `duration` необязателен, списки показывают только начало                                    |
| Диалог из планировщика перестанет создавать серию                | признак источника передаётся явно, покрывается тестом                                       |
| Пользователь ждёт разовую встречу в планировщике                 | поведение зафиксировано требованием R3: планировщик показывает только свои события          |
