# Proposal: единый источник встреч — `PermanentMeeting`

> Основание: замечание владельца 2026-11-24 по вчерашней версии
> (ветка `FUSIO-1307-livekit-shared-link`, HEAD `ab97fd3f7f`). Проверено на стенде `:8087`:
> разовая встреча, созданная из окна «Новая встреча», есть в календаре, но отсутствует и в таблице
> раздела «Встречи», и во вкладке «Группы».

## Why

Встречи хранятся в двух разных документах: постоянная — это `love.class.PermanentMeeting`, разовая —
`calendar.class.Event` с миксином `MeetingEventLink` и **без** документа встречи
(`createOneOffMeeting`, `permanentMeetingSchedule.ts:346`). Оба списка раздела строятся по
`PermanentMeeting`:

- таблица раздела «Встречи» — `MeetingsView.svelte:67`, `_class = love.class.PermanentMeeting`;
- вкладка «Группы» — `MeetingGroupsView.svelte:37`, тот же класс.

Следствие: всё, что создано как разовая встреча, не появляется ни в одном списке — только в календаре.
Пользователь видит «создал встречу, а её нигде нет».

Второе следствие: встречи, созданные в разделе «Встречи», попадают в планировщик (календарь), хотя по
требованию владельца планировщик должен показывать только события, созданные в самом планировщике.

## What changes

| #   | Требование владельца                                                                | Суть изменения                                                                                        |
| --- | ----------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| R1  | «В таблицах вкладки отображаются ВСЕ встречи: постоянные, разовые, скрытые»          | Любая встреча хранится как `PermanentMeeting`; разовая перестаёт создавать `Event`                     |
| R2  | «В „Группах“ только группы»                                                          | Вкладка «Группы» не меняется: те же документы, секции по `group`                                       |
| R3  | «В планировщике НЕ должны показываться встречи, созданные во вкладке „Встречи“»      | Создание из раздела «Встречи» пишет `calendar: false` и не создаёт серию; `Event` создаёт только планировщик |
| R4  | Решение владельца: длительность разовой встречи                                       | В `PermanentMeeting` добавляется поле `duration`                                                       |
| R5  | Решение владельца: судьба уже созданных встреч-событий                               | Миграция `Event + миксин → PermanentMeeting`, чтобы старые встречи попали в списки                     |

Переключатель представлений раздела «Встречи» (`Календарь / Таблица`) **не меняется**.

## Impact

- `models/love/src/index.ts` — поле `duration` в `TPermanentMeeting`, тип встречи в списках.
- `models/love/src/migration.ts` — миграция `event-meeting-to-permanent`.
- `plugins/love/src/types.ts` — `duration` в интерфейсе `PermanentMeeting`.
- `plugins/love-resources/src/permanentMeetingSchedule.ts` — `PermanentMeetingInput.duration`,
  `createOneOffMeeting` создаёт встречу вместо события.
- `plugins/love-resources/src/components/CreateMeetingDialog.svelte` — `calendar: false` для создания из
  раздела «Встречи», длительность в форме, тумблер календаря только для планировщика.
- `plugins/love-resources/src/components/MeetingsView.svelte`, `MeetingGroupsView.svelte` — проверка
  состава строк после смены хранения.
- `plugins/love-assets/lang/*.json` (12 локалей) — новые строки.
- `docs/love.md`, `docs/features/office-meetings.md` — описание хранения встреч.

## Out of scope

- Переключатель «Календарь / Таблица» в разделе «Встречи» — остаётся как есть.
- Приглашение гостя письмом (пункт 2.3 `love-meetings-unified-views`) — отдельная задача.
- Группировка и сортировка настроек вида — закрыты в `ab97fd3f7f`.
