# Design

## Context

- Планировщик — это `calendar.class.Schedule` (`owner`, `title`, `meetingDuration`, `meetingInterval`, `availability`).
  Love вешает на него миксин `MeetingSchedule` и заполняет только `room` (`createMeetingSchedule`,
  `DocCreateExtension` с телом `MeetingScheduleData.svelte`).
- Форма события — `calendar.class.Event` с `DocCreateExtension` love (`createMeeting`, тело `MeetingData`), миксин
  `MeetingEventLink` ставится на мастер серии.
- `TMeetingSchedule.meetingId` объявлен в модели, но нигде не пишется — под связь с постоянной встречей он и создан.
- Вкладка «Встречи» — `SpecialView _class={love.mixin.MeetingEventLink}` в `Hall.svelte`.

## Goals

- Создавать постоянную встречу из планировщика и из формы события, с участниками и промежутком.
- Хранить промежуток на самой постоянной встрече, а не только в планировщике.
- Показать постоянные встречи во вкладке «Встречи».

## Decisions

1. **Промежуток — на `PermanentMeeting`.** Новое необязательное `repeatEvery?: number` (мс). В планировщике поле
   по умолчанию заполняется из `Schedule.meetingInterval` (он уже в минутах — переводим в мс), в форме события
   пользователь задаёт его сам. Альтернатива «только `meetingInterval`» отклонена: в форме события такого поля нет,
   а связь через запись планировщика не обязательна.
2. **Связь — через `TMeetingSchedule.meetingId`.** Поле уже объявлено; используем его вместо нового. В форме события
   связь не нужна: там постоянная встреча создаётся рядом с событием, ссылку хранит само событие (миксин).
3. **Вкладка «Встречи» показывает два списка.** События остаются `SpecialView` на миксине; постоянные встречи —
   второй `SpecialView` на `PermanentMeeting` в той же вкладке, с заголовком «Постоянные встречи». Так не нужно
   писать новый агрегирующий компонент и не ломается пагинация/фильтры таблиц.
4. **Создание — в клиенте.** `DocCreateExtension` уже живут в `plugins/love-resources`, сервер не меняется:
   постоянная встреча — обычный `Space`, его создаёт клиент с правами пользователя.

## Risks

| Риск | Как снимаем |
|---|---|
| Путь планировщика создаёт документы дважды при повторном сохранении | Создаём постоянную встречу только в фазе `post` создания записи и только если `meetingId` ещё пуст |
| Новая встреча теряет комнату | Комната берётся из `store.room`, как сейчас; если её нет — переключатель недоступен |
| Вкладка «Встречи» задваивает строки | Постоянная встреча из события не создаётся: событие остаётся событием, отдельного `PermanentMeeting` у него нет |
| Миграция не нужна | `repeatEvery` необязательное, `meetingId` раньше не писался — данных для переноса нет |

## Open Questions

1. Должен ли `repeatEvery` влиять на сервис love (открывать сессии по этому промежутку) или это только подсказка для
   планировщика. Сейчас поле описывает намерение; поведение открытия сессий не меняется.
2. Нужен ли показ `repeatEvery` в панели постоянной встречи или достаточно планировщика.
