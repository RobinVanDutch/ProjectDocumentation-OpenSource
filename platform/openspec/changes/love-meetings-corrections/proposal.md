## Why

За три дня в ветке `FUSIO-1307-livekit-shared-link` накопился большой объём UI- и сервисных правок вокруг встреч:
календарный путь создания, комнаты, «Встречи»/«Постоянные встречи», группы, гостевой вход, иконки в планировщике.
Три результата оказались неприемлемыми для владельца:

1. **Ссылка не перевыпускается при переносе времени.** Гостевая ссылка — это shortId от payload
   `{ eventId, linkVersion }` (`services/love/src/guests.ts:333`), поэтому её «перевыпуск» — это увеличение
   `linkVersion`. Сейчас `linkVersion` меняет только явный отзыв в UI (`revokeMeetingLink` /
   `revokePermanentMeetingLink`, `plugins/love-resources/src/utils.ts:410-424`); перенос события в календаре,
   правка времени в попапе события и смена расписания постоянной встречи ссылку **не** трогают. Пользователь
   переносит встречу на завтра и продолжает рассылать старую ссылку, которая ведёт к старому времени
   (или уже «истекла» по `afterTtl`, потому что `lastMeetingEnd`/`nextOccurrence` считаются от другого слота).
2. **Отображение запланированной встречи переделано без запроса.** В строке списка постоянных встреч клик
   открывал окно настроек, у строки были «копировать ссылку / вступить / удалить или покинуть» и счётчик
   встреч в заголовке группы. В рамках правок 2026-11-11…12 клик переведён на `openDoc` (полная карточка
   документа), добавлена шестерёнка, счётчик убран (`PermanentMeetingsList.svelte`), изменена кнопка входа
   в карточке (`EditScheduledMeeting.svelte`) и добавлена своя разметка значка повтора на плитке события
   (`MeetingEventBadge.svelte`). Владелец считает это регрессом UX: прежнее отображение было нормальным.
3. **403 на входе во встречу.** Два независимых источника:
    - платформенный: `$or` не поддерживается Postgres-адаптером — запрос исключений серии
      (`occurrenceOverrides`, `services/love/src/workspaceClient.ts:778-796`) транслируется в
      `event.data#>>'{$or}' = ARRAY['[object Object]', …]` и падает с `operator does not exist: text = text[]`;
      исключения (перенос/отмена вхождения) не читаются никогда, поэтому перенесённое вхождение даёт
      `no-occurrence` → `403 {"error":"Meeting is not open"}` (`services/love/src/main.ts:622`);
    - клиентский: этот 403 не обрабатывается и вылетает как непойманная ошибка (`LoveServiceError` из
      `loveClient.ts:148` через `joinMeetingBySession`, `meetings.ts:246`) — в dev-сборке это красный оверлей
      «Uncaught runtime errors», в прод-сборке — мёртвая кнопка «Присоединиться».
4. **Нет тестового покрытия новых сценариев.** Появились комнаты в форме создания, перехват занятой комнаты,
   текст «ссылка скопирована», пароль гостя, сообщение об отозванной ссылке, группы, иконки постоянной встречи —
   всё проверялось руками; часть сценариев вообще не проверялась (перехват комнаты), потому что для этого нужен
   второй участник и живой LiveKit.

## What Changes

1. **Перевыпуск ссылки при смене времени встречи.** Любая смена времени/расписания встречи (мастер события:
   `date`, `dueDate`, `rules`, `rdate`, `exdate`; `PermanentMeeting`: расписание/период/время) MUST увеличивать
   `linkVersion` и очищать `linkId`, то есть старая ссылка перестаёт открывать встречу, а следующая выдача даёт
   новую. Реализация — серверные триггеры (`onEventUpdate` в `server-plugins/calendar-resources`,
   `OnPermanentMeetingUpdate` в `server-plugins/love-resources`), чтобы покрыть и drag&drop в планировщике,
   и правку в попапе, и API-путь. Перенос **одного вхождения** серии ссылку не перевыпускает (серия та же).
2. **Откат чужого UI.** Отображение запланированной встречи возвращается к состоянию до правок (`git HEAD`):
   строка списка постоянных встреч снова открывает окно настроек, набор действий и счётчик группы восстанавливаются,
   карточка встречи и плитка события выглядят как раньше. Из добавленного остаётся только то, что просили явно:
   иконка-различие «постоянная встреча / обычная» в планировщике — и добавляется она **на существующую разметку**,
   без переделки вида и без своих стилей поверх готовых.
3. **403 починен целиком.** (а) `occurrenceOverrides` перестаёт использовать `$or` (два запроса без `$or`
   с фильтрацией по времени в памяти либо чтение по `recurringEventId` + фильтр), (б) отказ резолва
   (`no-occurrence`, `403`) обрабатывается клиентом как штатный ответ: участнику показывается человеческий текст
   («встреча ещё не началась» / «уже прошла», с ближайшим вхождением), а не runtime-ошибка; (в) в логах сервиса
   не остаётся `Failed to read occurrence overrides` на штатной работе.
4. **Покрытие UI/UX тестами.** Каждый сценарий, сделанный 2026-11-09 … 12, получает тест: компонентные
   (vitest + jsdom) для того, что проверяется без стенда, и Playwright-sanity (`tests/sanity/tests/love/*`,
   `tests/sanity/tests/calendar/*`) для сквозных путей. Отдельно — сценарии, которые сейчас не покрыты:
   перехват занятой комнаты, отзыв ссылки, гостевой пароль, копирование ссылки, группы.
5. **Полный прогон.** Все unit-наборы затронутых пакетов, sanity love/calendar целиком, плюс ручной прогон
   каждого сценария через Playwright на стенде; итог — в `handoff.md` с числом реальных падений и списком флаков.

## Правила работы (пункт 6, действует всегда)

- Не менять внешний вид и поведение экранов, о которых не просили. Правка UI допустима только в объёме просьбы.
- Сначала спека, потом код: пункт сначала попадает в `tasks.md`, потом в код.
- `docs/` в репозитории платформы не трогать; спека живёт здесь.

## Capabilities

### New Capabilities

- `love-meetings` (дельта): перевыпуск ссылки при смене времени, штатная обработка отказа входа, чтение исключений
  серии на Postgres, неизменность отображения запланированной встречи без явного запроса.

## Impact

- `services/love/src/workspaceClient.ts` — чтение исключений серии без `$or`, ошибки резолва.
- `services/love/src/main.ts` — контракт ответа `resolveSession`/`/guestInfo` при закрытом окне.
- `server-plugins/calendar-resources/src/index.ts` — перевыпуск ссылки при правке мастера события.
- `server-plugins/love-resources/src/index.ts` — перевыпуск ссылки при смене расписания постоянной встречи.
- `plugins/love-resources/src/{loveClient,meetings}.ts` — обработка 403/`no-occurrence` без непойманной ошибки.
- `plugins/love-resources/src/components/{PermanentMeetingsList,EditScheduledMeeting,MeetingEventBadge}.svelte` —
  откат отображения.
- `tests/sanity/tests/love/**`, `tests/sanity/tests/calendar/**`, `src/__tests__/**` пакетов — покрытие.

## Что НЕ входит

- Переделка дизайна списка/карточки/плитки по вкусу: только возврат к прежнему виду.
- Отмена/перенос вхождения через сервис (сейчас это делает календарь) — не меняем владельца операции.
