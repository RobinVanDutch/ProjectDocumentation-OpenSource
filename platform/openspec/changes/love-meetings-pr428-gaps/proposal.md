# Proposal

## Why

PR #428 («FUSIO-1307: Recurrent meetings») накатан на ветку `FUSIO-1307-livekit-shared-link` (коммит `ca12e587e5`).
Он заменил модель встреч: статуса `MeetingStatus.Scheduled` больше нет, сессию создаёт `resolveSession`,
ссылка — указатель на серию с политикой `meetingAccess`, постоянная встреча — отдельный класс `PermanentMeeting`.
Сверка показала (`audit-pr-428.md` §2–§3): этап 2 плана закрыт полностью, этап 1 — только в части отмены,
этапы 3, 5, 6(частично), 7, 8 не сделаны, этап 4 закрыт частично. Этот change собирает оставшееся
в один пакет работ и описывает поведение, которое PR принёс, но которое нигде не зафиксировано
(RSVP, пароль гостя, rate limit).

## What Changes

- **Перенос вхождения серии** (этап 1): `meetingOccurrences` вычитает `exdate`, но не читает override —
  перенесённая встреча открывается по старому времени. Нужно учитывать новые времена и в окне входа,
  и в `occurrence` сессии.
- **Владелец постоянной встречи** (этап 3): серверная проверка, что `owners` остаются в `members`,
  и запрет такой правки в UI.
- **Язык постоянной встречи** (этап 6.1): сделан в §12 `audit-pr-428.md` — дефолт языка берётся из интерфейса;
  в этом change только фиксируется требованием.
- **Режимы гостя постоянной встречи** (этап 6.2): `/guestInfo` не должен отдавать `after` для `kind === 'meeting'`.
- **Навигатор: путь** (этап 4.1): `navigateToOfficeDoc`/`backOrOpen` больше не режут `loc.path` до трёх сегментов —
  сделано в §12, фиксируется требованием.
- **Мёртвые поля модели** (этап 7): `linkId` объявлен и не пишется — закрываем не удалением, а записью shortId
  при выдаче ссылки (концепция PR #428 сохраняется), `TMeetingSchedule.meetingId` остаётся как в PR.
- **Описание того, что PR уже привёз**: пароль гостя, rate limit гостевого входа, авторизация HTTP API,
  RSVP календаря — отдельными capability, чтобы база требований совпадала с кодом.
- **Документация**: `docs/love.md` §8.3 теряет контракт `/guestJoin` (`personToken`, `400` без имени) при слиянии,
  `docs/features/office-meetings.md` продолжает описывать `startOnLink`/`Scheduled`/`restartMeeting`.

Не входит в эту итерацию (перенесено решением от 2026-11-03):

- **Перенос вхождения серии** (`meetingOccurrences` + override из `PersonSpace`). Источник перенесённых времён не согласован,
  без него задача превращается в переделку модели календаря — уходит в следующую итерацию вместе с e2e на перенос.
- **Внеплановый старт по ссылке** (этап 5) — **решение 2026-11-03: не делаем.** Сценарий «созвониться в любой момент»
  закрывает `PermanentMeeting`; для серии внеплановый старт ломает окно вхождения (оно защищает приватность),
  инвариант «одна живая сессия на вхождение» и привязку `occurrence` к календарю.
- **Особые права владельца воркспейса на ссылку.** Ссылку создаёт участник встречи, остальные по ней подписываются;
  отдельной ветки «владелец воркспейса меняет/стартует ссылку по расписанию» нет и быть не должно —
  эндпоинты ссылки и пароля уже требуют только участия (`authorizeTarget`).

## Capabilities

### New Capabilities

- `love-meeting-occurrences`: какие вхождения серии существуют и когда по ним открывается сессия — отмена, перенос, `nextOccurrence`.
- `love-permanent-meeting`: постоянная встреча как документ — владелец остаётся участником, язык, режимы гостя.
- `office-navigator`: навигатор офиса — сегмент в пути сохраняется при открытии документа во время звонка.
- `love-meeting-model`: модель встреч не содержит мёртвых полей ссылки и расписания.
- `guest-access`: доступ гостя по ссылке — пароль, rate limit, авторизация эндпоинтов.
- `calendar-rsvp`: ответы участников на события календаря и их сводка.

### Modified Capabilities

Нет: в `openspec/specs/` пока пусто, все capability этого проекта вводятся впервые.

## Impact

- Клиент: `plugins/love/src/utils.ts` (`meetingOccurrences`, `resolveOccurrence`), `plugins/love-resources/src/utils.ts`
  (`navigateToOfficeDoc`), `plugins/love-resources/src/components/guest/GuestMeetingApp.svelte`,
  панель свойств постоянной встречи (редактор участников).
- Сервер: `services/love/src/workspaceClient.ts` (`findMeetingTarget`, `resolveSession`),
  `services/love/src/guests.ts` (`/guestInfo`), `server-plugins/love-resources/src/index.ts` (валидация `members`).
- Модель: `models/love/src/index.ts` (`linkId`, `TMeetingSchedule`), миграция при удалении полей — **BREAKING** для внешних клиентов, читающих `linkId`.
- Тесты: unit на перенос, на валидацию `members`, `types/sanity` — e2e отмены и переноса вхождения.
- Документация: `docs/love.md`, `docs/features/office-meetings.md`, `platform-docs` (`communication/invite-link`).
