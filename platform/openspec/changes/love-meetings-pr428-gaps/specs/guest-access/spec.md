# Spec Delta

## Purpose

Доступ гостя по ссылке: пароль, ограничение попыток и авторизация эндпоинтов. Поведение принесено PR #428,
до этого change оно нигде не описано.

## ADDED Requirements

### Requirement: Пароль гостя хранится только на сервере

Встреча MAY иметь пароль гостя. Система MUST хранить его только на сервере: pbkdf2-sha256 (соль на встречу), наружу не отдаётся; `/guestInfo` до ввода пароля сообщает только требование пароля, без названия и времени встречи.

#### Scenario: У ссылки есть пароль

- **WHEN** гость открывает ссылку встречи с паролем
- **THEN** лобби просит пароль и не раскрывает название встречи

#### Scenario: Неверный пароль

- **WHEN** гость вводит неверный пароль
- **THEN** ответ `401`, о встрече ничего не сообщается

#### Scenario: Пароль снят

- **WHEN** участник снимает пароль
- **THEN** следующее открытие ссылки не требует пароля

### Requirement: Попытки ввода пароля ограничены

Система MUST ограничивать число неудачных попыток: 10 промахов на пару «ссылка + IP» закрывают вход на 15 минут
с ответом `429`.

#### Scenario: Серия неверных паролей

- **WHEN** с одного IP десять раз подряд введён неверный пароль к одной ссылке
- **THEN** следующие попытки получают `429` в течение 15 минут

#### Scenario: Успешный вход

- **WHEN** гость ввёл верный пароль
- **THEN** счётчик попыток для этой пары сбрасывается

### Requirement: Эндпоинты ссылки и пароля требуют авторизации

`GET /meetingLink`, `POST /meetingPassword`, `POST /resolveSession` MUST отклонять запрос без токена (`401`),
не участнику встречи (`403`) и несуществующую встречу (`404`). Роль владельца workspace MUST NOT давать
особых прав на ссылку: ссылку выдаёт и меняет участник встречи, остальные по ней подписываются.

#### Scenario: Запрос без токена

- **WHEN** запрос приходит без токена
- **THEN** ответ `401`

#### Scenario: Запрос не от участника

- **WHEN** ссылку запрашивает пользователь, не являющийся участником встречи, включая владельца workspace
- **THEN** ответ `403`, ссылка не выдаётся и пароль не ставится

### Requirement: Имя гостя обязательно, личность стабильна

`/guestJoin` MUST требовать имя и фамилию (`400` с текстом о необходимости ввести имя). Если клиент не передал
свой идентификатор гостя, сервер MUST вывести стабильный идентификатор из встречи и имени, чтобы повторный вход
не создавал вторую персону.

#### Scenario: Гость без имени

- **WHEN** запрос `/guestJoin` приходит без имени или фамилии
- **THEN** ответ `400`, персона не создаётся

#### Scenario: Клиент без локального идентификатора

- **WHEN** запрос приходит с именем, но без идентификатора гостя
- **THEN** ответ `200`, персона создаётся или находится по выведенному идентификатору

#### Scenario: Повторный вход

- **WHEN** тот же гость повторно входит по той же ссылке с тем же именем
- **THEN** используется та же персона
