# Spec Delta

## Purpose

Какие вхождения серии встреч существуют и по каким из них можно открыть сессию.

## ADDED Requirements

### Requirement: Отменённое вхождение не открывает сессию

Система MUST NOT открывать сессию для вхождения, исключённого из серии (`exdate`). Набор вхождений серии
считается как rules + `rdate` − `exdate`.

#### Scenario: Вхождение отменено

- **WHEN** участник переходит по ссылке в момент, когда вхождение серии исключено
- **THEN** сессия не создаётся, ответ содержит следующее действительное вхождение

### Requirement: Перенесённое вхождение открывается в новое время

Система MUST считать окно входа по времени перенесённого вхождения, а не по расписанию мастера. Сессия
перенесённого вхождения MUST хранить новое время как своё `occurrence`.

#### Scenario: Встреча перенесена на два часа

- **WHEN** вхождение серии перенесено на более позднее время и участник входит в новое время
- **THEN** сессия открывается, `occurrence` соответствует новому времени

#### Scenario: Старое время перенесённого вхождения

- **WHEN** участник входит по ссылке во время, от которого вхождение было перенесено
- **THEN** сессия этого вхождения не открывается, предлагается новое время

### Requirement: Отказ называет следующее вхождение по календарю

Ответ «встреча не открыта» MUST содержать ближайшее будущее вхождение с учётом отмен и переносов.

#### Scenario: Вне окна действующего вхождения

- **WHEN** участник входит вне окна вхождения, а следующее вхождение перенесено
- **THEN** в ответе указано перенесённое время, а не время из расписания мастера
